<task type="auto">
  <name>Task 1: Create sentence API routes and update worker with real analysis logic</name>
  <files>src/routes/sentences.ts, src/workers/index.ts</files>
  <action>
1. Create `src/routes/sentences.ts` (Fastify route plugin, NOT wrapped in fp() -- routes are encapsulated per project convention):
   - `POST /sentences`:
     - Accept JSON body: `{ text: string, sourceBook?: string }`
     - Validate: `text` must be non-empty string (use Fastify schema validation or manual check, return 400 if empty)
     - Enqueue job: `fastify.analysisQueue.add('analyze', { text, sourceBook })`
     - Return 202: `{ jobId: job.id }`
   - `GET /sentences/:jobId/status`:
     - Get job from queue: `fastify.analysisQueue.getJob(jobId)`
     - If not found, return 404: `{ error: 'Job not found' }`
     - Get state: `await job.getState()`
     - If completed: return `{ status: 'completed', result: job.returnvalue }`
     - If failed: return `{ status: 'failed', error: job.failedReason }`
     - Otherwise: return `{ status: state }` (waiting, active, delayed, etc.)

2. Update `src/workers/index.ts`:
   - Replace the placeholder processor with real logic:
     a. Import `analyzeSentence` from `../lib/ai/analyze-sentence.ts`
     b. Import `storeAnalysisResults` from `../services/analysis.ts`
     c. Import `createDb` from `../db/index.ts`
     d. Create DB instance: `const db = createDb(process.env.DATABASE_URL!)`
     e. In processor:
        - Extract `{ text, sourceBook }` from `job.data`
        - Call `const analysis = await analyzeSentence(text)`
        - Call `const result = await storeAnalysisResults(db, text, sourceBook, analysis)`
        - Return result
     f. Add `concurrency: 2` to worker options (limit parallel AI calls)
   - Keep existing error/completion logging and SIGTERM handler

Use .ts import extensions everywhere.
  </action>

    <automated>npx tsc --noEmit</automated>
  </verify>
