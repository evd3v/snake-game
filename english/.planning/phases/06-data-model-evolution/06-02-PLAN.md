   - Update POST /words/:wordId/srs-card endpoint:
     - This endpoint needs rethinking. It currently takes a wordId and creates a vocabulary SRS card. After migration, it should take a wordSenseId. Change the route to `POST /word-senses/:wordSenseId/srs-card`.
     - Update the createSrsCard call to use `{ wordSenseId }`.
     - Update the conflict check query: `eq(srsCards.wordSenseId, wordSenseId)` instead of `eq(srsCards.wordId, wordId)`.

3. **src/routes/words.ts** - Update both endpoints:
   - GET /sentences/:sentenceId/words:
     - Import `wordSenses` from schema
     - After getting word IDs from sentenceWords join, also join wordSenses to get translation and familiarity per sense
     - The query needs to: join words -> sentenceWords (for sentence filter), then LEFT JOIN wordSenses to get translation/familiarity
     - Since a word can have multiple senses, return ALL senses for each word. Restructure the response: each word has `senses: [{ partOfSpeech, translation, familiarity }]`
     - OR simpler: keep flat structure but include partOfSpeech. For backward compatibility with the bot, keep the flat structure and pick the FIRST sense (most words will have just one sense initially).
     - Decision: Keep flat structure for now. LEFT JOIN word_senses on word_id, pick first sense. Return: id, lemma, cefrLevel, thematicCluster, position, translation (from word_senses), familiarity (from word_senses), partOfSpeech (from word_senses). If no sense exists (shouldn't happen after migration), return null for translation/familiarity.
     - For hasSrsCard check: query srs_cards WHERE wordSenseId IN (select id from word_senses where word_id IN wordIds). This is needed because the old check used srs_cards.wordId which no longer exists.
   - PATCH /words/:id/familiarity:
     - This now updates word_senses.familiarity, not words.familiarity.
     - Change the route to accept a word sense ID or keep word ID and update all senses for that word.
     - Decision: Keep as PATCH /words/:id/familiarity for backward compatibility but update ALL senses for that word_id. Import wordSenses, update where `eq(wordSenses.wordId, id)`.

4. **src/routes/dashboard.ts** - Update all 4 raw SQL queries:
   - GET /dashboard/stats:
     - Change `count(distinct ${srsCards.wordId})` to `count(distinct ${srsCards.wordSenseId})` for wordsWithCards count.
     - Actually this counts unique word_sense_ids with cards. For "total words" we still count words table rows. The math still works: totalWords - (number of words that have at least one sense with a card).
     - Better approach: count words that have at least one sense with a card:
       ```sql
       SELECT count(DISTINCT ws.word_id)::int AS "wordsWithCards"
       FROM srs_cards sc
       JOIN word_senses ws ON ws.id = sc.word_sense_id
       WHERE sc.card_type = 'vocabulary'
       ```
   - GET /dashboard/weak-spots (vocabulary):
     - Change JOIN from `JOIN words w ON w.id = sc.word_id` to `JOIN word_senses ws ON ws.id = sc.word_sense_id JOIN words w ON w.id = ws.word_id`
     - Select `ws.translation` instead of `w.translation`
   - GET /dashboard/clusters:
     - Change LEFT JOIN from `LEFT JOIN srs_cards sc ON sc.word_id = w.id` to `LEFT JOIN word_senses ws ON ws.word_id = w.id LEFT JOIN srs_cards sc ON sc.word_sense_id = ws.id`
     - Keep `AND sc.card_type = 'vocabulary'` on the srs_cards join
