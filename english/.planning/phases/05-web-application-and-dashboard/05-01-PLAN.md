  <files>web/package.json, web/vite.config.ts, web/tsconfig.json, web/tsconfig.app.json, web/tsconfig.node.json, web/index.html, web/src/main.ts, web/src/App.vue, web/src/router/index.ts, web/src/api/client.ts, web/src/types/api.ts</files>
  <action>
  Run `npm create vue@latest web -- --typescript --router --pinia` from the project root to scaffold into `web/`. Then:

  1. **vite.config.ts**: Add API proxy so `/api/*` requests forward to `http://localhost:3000` with path rewrite removing the `/api` prefix. Add `@` alias for `./src`. See RESEARCH Pattern 1.

  2. **web/src/api/client.ts**: Create a thin fetch wrapper with two exports:
     - `apiGet<T>(path: string): Promise<T>` -- GET request to `${BASE_URL}${path}`, throws on non-ok
     - `apiPost<T>(path: string, body?: unknown): Promise<T>` -- POST with JSON body
     - `BASE_URL` reads from `import.meta.env.VITE_API_URL` falling back to `'/api'`

  3. **web/src/types/api.ts**: Create shared TypeScript interfaces for dashboard responses:
     ```typescript
     export interface ProgressStats {
       words: { new: number; learning: number; known: number };
       grammar: { new: number; learning: number; known: number };
     }
     export interface WeakSpot {
       id: number;
       name: string;        // lemma for words, pattern for grammar
       translation?: string; // only for words
       description?: string; // only for grammar
       type: 'vocabulary' | 'grammar';
       failRate: number;
       totalReviews: number;
     }
     export interface DayActivity {
       date: string; // YYYY-MM-DD
       reviews: number;
       additions: number;
     }
     export interface ClusterStats {
       cluster: string;
       total: number;
       new: number;
       learning: number;
       known: number;
     }
     ```

  4. **web/src/router/index.ts**: Define three routes with lazy-loaded views:
     - `/` -> DashboardView.vue
     - `/sentences` -> SentenceInputView.vue
     - `/vocabulary` -> VocabularyView.vue
     Create minimal placeholder `.vue` files for each view (just a `<template><div>Page Name</div></template>`).

  5. **web/src/App.vue**: Root component with `<nav>` containing router-links to Dashboard, Sentences, Vocabulary. Below nav, `<router-view />`.

  6. After scaffolding, run `cd web && npm install` and `cd web && npm run build` to verify the SPA builds.

  Remove any default boilerplate components and styles that `create-vue` generates (HelloWorld.vue, TheWelcome.vue, etc.).

  <name>Task 2: Create dashboard API endpoints with tests</name>
  <files>src/routes/dashboard.ts, tests/dashboard-api.test.ts</files>
  <behavior>
    - GET /dashboard/stats returns { words: { new, learning, known }, grammar: { new, learning, known } } with correct counts from srs_cards grouped by state and card_type, plus words without SRS cards counted as "new"
    - GET /dashboard/weak-spots returns array of { id, name, translation?, description?, type, failRate, totalReviews } for items with >= 2 reviews, ordered by failRate DESC, limit 10 each
    - GET /dashboard/activity returns array of { date, reviews, additions } for last 365 days, combining review_logs counts and sentence creation counts per day
    - GET /dashboard/clusters returns array of { cluster, total, new, learning, known } grouped by thematic_cluster, ordered by total DESC
    - All endpoints return 200 with empty/zero data when no records exist
  </behavior>
  <action>
  Create `tests/dashboard-api.test.ts` following the existing test patterns (see `tests/review-api.test.ts` for reference -- uses `buildServer`, direct db inserts, and supertest-style `.inject()`).

  Tests should:
  - Seed test data (words, srs_cards, review_logs, sentences, grammar_patterns) using `fastify.db.insert()`
  - Verify each endpoint returns correct shape and values
  - Test empty-state responses (no data yet)

  Then create `src/routes/dashboard.ts` as a Fastify plugin (same pattern as other route files: `const dashboardRoute: FastifyPluginAsync = async (fastify) => { ... }; export default dashboardRoute;`).

  Four endpoints:

  **GET /dashboard/stats (DASH-01)**:
  - Query srs_cards grouped by card_type + state to get counts
  - Query total words count (words without SRS cards = additional "new")
  - Return `ProgressStats` shape

  **GET /dashboard/weak-spots (DASH-02)**:
  - Join srs_cards -> words/grammar_patterns -> review_logs
  - Compute fail_rate = COUNT(rating <= 2) / COUNT(*) for items with >= 2 reviews
  - Return top 10 vocabulary + top 10 grammar weak spots combined, ordered by failRate DESC

  **GET /dashboard/activity (DASH-03)**:
  - Aggregate review_logs by DATE(reviewed_at) for last 365 days
  - Aggregate sentences by DATE(created_at) for last 365 days
  - Combine into single array of DayActivity records (one per unique date)

  **GET /dashboard/clusters (DASH-04)**:
  - Group words by thematic_cluster
  - LEFT JOIN srs_cards to get state breakdown (words without SRS cards count as "new")
  - Filter out NULL thematic_cluster
  - Order by total DESC

  Use Drizzle ORM for all queries (sql template for complex aggregations where needed -- `import { sql } from 'drizzle-orm'`). Reference existing route patterns for Fastify plugin structure.
