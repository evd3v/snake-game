<task type="auto" tdd="true">
  <name>Task 1: Review API routes with vocabulary context and SRS card creation hooks</name>
  <files>src/routes/review.ts, src/bot/services/api-client.ts, src/bot/handlers/vocabulary.ts, tests/review-api.test.ts</files>
  <behavior>
    - GET /review/due returns array of due cards with word data (lemma, translation) and original sentence text
    - GET /review/due returns empty array when no cards are due
    - GET /review/due?limit=5 limits results to 5
    - Each vocabulary card in response includes sentenceText from original sentence (SRS-05)
    - Each grammar card in response includes a random unused cloze exercise (sentence with ___, answer, hint)
    - POST /review/:cardId/rate with { rating: 3 } updates card scheduling and returns next due date
    - POST /review/:cardId/rate with invalid rating returns 400
    - POST /review/:cardId/rate for non-existent card returns 404
    - POST /words/:wordId/srs-card creates an SRS card for a vocabulary word (idempotent)
    - Bot vocabulary handler calls createSrsCard API after setting familiarity
  </behavior>
  <action>
    1. Create `src/routes/review.ts` as a Fastify plugin (same pattern as words.ts -- plain export, NOT wrapped in fp()):

       GET /review/due:
       - Query params: limit (optional, default 20)
       - Calls getDueCards(fastify.db, limit) from srs service
       - For each vocabulary card: join words + sentenceWords + sentences to get lemma, translation, cefrLevel, sentenceText (first sentence where word appears). This fulfills SRS-05 (original book sentence as context).
       - For each grammar card: join grammarPatterns to get pattern/description, query grammarExercises for one unused exercise (WHERE used = false AND grammarPatternId = X ORDER BY difficultyLevel ASC LIMIT 1). This fulfills SRS-06 (difficulty progression -- simple exercises served first).
       - Return array of enriched card objects: { cardId, cardType, state, due, word?: { lemma, translation, cefrLevel }, sentence?: string, exercise?: { id, sentence, answer, hint, difficultyLevel }, pattern?: { pattern, description } }

       POST /review/:cardId/rate:
       - Body: { rating: number } (1=Again, 2=Hard, 3=Good, 4=Easy)
       - Validate rating is 1-4, return 400 if not
       - Check card exists, return 404 if not
       - Call rateCard(fastify.db, cardId, rating) from srs service
       - If card is grammar type and has exercise, mark that exercise as used=true
       - Return { success: true, nextDue: <date> }

       POST /words/:wordId/srs-card:
       - Creates vocabulary SRS card via createSrsCard(db, 'vocabulary', { wordId })
       - Idempotent (onConflictDoNothing)
       - Returns 201 with card data

    2. Add to `src/bot/services/api-client.ts`:
       - `createSrsCard(wordId: number)`: POST to /words/:wordId/srs-card

    3. Update `src/bot/handlers/vocabulary.ts`:
       - After successful `apiClient.setFamiliarity(wordId, ...)` in the fam callback handler, also call `apiClient.createSrsCard(wordId)`. Wrap in try/catch -- SRS card creation failure should not break familiarity flow.

    4. Write tests in `tests/review-api.test.ts`:
       - Use buildTestApp helper for Fastify test instance
       - Seed DB with words, sentences, sentenceWords, srsCards (with due in past for due cards, future for not-due)
       - Test GET /review/due returns due cards with word data and sentence context
       - Test GET /review/due with no due cards returns empty array
       - Test POST /review/:cardId/rate with valid rating returns success
       - Test POST /review/:cardId/rate with invalid rating returns 400
       - Test POST /words/:wordId/srs-card creates card
       - Test POST /words/:wordId/srs-card is idempotent
  </action>
