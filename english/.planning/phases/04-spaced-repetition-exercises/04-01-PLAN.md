  <name>Task 1: Schema, SRS service, and unit tests</name>
  <files>src/db/schema/grammar-exercises.ts, src/db/schema/review-logs.ts, src/db/schema/index.ts, src/services/srs.ts, tests/srs-service.test.ts</files>
  <behavior>
    - createSrsCard('vocabulary', { wordId: 1 }) inserts a new srs_cards row with state='new' and due=now
    - createSrsCard('grammar', { grammarPatternId: 5 }) inserts with grammar type
    - createSrsCard with same wordId twice (onConflictDoNothing) does not throw
    - toFsrsCard(dbRow) maps string state to numeric: 'new'->0, 'learning'->1, 'review'->2, 'relearning'->3
    - toDbState(0) returns 'new', toDbState(3) returns 'relearning'
    - rateCard(db, cardId, Rating.Good) updates due date to future, increments reps
    - rateCard on a 'new' card transitions state to 'learning'
    - getDueCards(db) returns only cards where due <= now, ordered by due ASC
    - getDueCards(db, 5) limits to 5 results
    - Grammar exercises difficulty progression: getDueCards returns exercises ordered by difficulty level 1->2->3
  </behavior>
  <action>
    1. Run `npm install ts-fsrs` to add the FSRS library.

    2. Create `src/db/schema/grammar-exercises.ts`:
       - grammarExercises table: id (identity PK), grammarPatternId (FK to grammarPatterns.id), sentence (text, has "___" gap), clozeAnswer (text), difficultyLevel (integer 1-3, default 1), hint (text, nullable), used (boolean, default false), createdAt (timestamp, defaultNow).
       - Follow existing schema patterns (integer().primaryKey().generatedAlwaysAsIdentity()).

    3. Create `src/db/schema/review-logs.ts`:
       - reviewLogs table: id (identity PK), srsCardId (FK to srsCards.id), rating (integer 1-4), elapsedDays (integer), scheduledDays (integer), state (cardStateEnum, state BEFORE review), reviewedAt (timestamp, defaultNow).

    4. Update `src/db/schema/index.ts` to export grammarExercises and reviewLogs from new files.

    5. Run `npx drizzle-kit generate` to create the migration, then `npx drizzle-kit push` to apply.

    6. Create `src/services/srs.ts` with:
       - `toFsrsCard(row)`: Maps DB row to ts-fsrs Card object. Maps string state enum to numeric State (new=0, learning=1, review=2, relearning=3). Handles nullable fields with defaults.
       - `toDbState(fsrsState: number)`: Maps numeric State back to string.
       - `createSrsCard(db, cardType, { wordId?, grammarPatternId? })`: Inserts new srs_cards row using createEmptyCard() from ts-fsrs for initial FSRS values. Uses onConflictDoNothing for idempotency (may need unique constraint -- use insert-only, check before insert if needed).
       - `rateCard(db, cardId, rating: Rating)`: Selects card row, converts to FSRS card, calls `scheduler.next(card, rating, new Date())`, persists updated card fields, inserts review_logs entry.
       - `getDueCards(db, limit = 20)`: Selects from srs_cards WHERE due <= NOW() ORDER BY due ASC LIMIT limit.
       - Module-level `const scheduler = fsrs({ request_retention: 0.9, enable_fuzz: true })`.

    7. Write tests in `tests/srs-service.test.ts` covering all behaviors above. Use the existing test helper pattern (buildTestApp/cleanupTestApp for DB access). For FSRS tests, create cards in DB, rate them, verify state transitions and due date changes.
  </action>
  <verify>
    <automated>npm test -- tests/srs-service.test.ts</automated>
  </verify>
  <done>SRS service creates/rates/queries cards via FSRS. Grammar exercises and review logs tables exist with migration. All unit tests pass.</done>
