1. Create `src/services/reader-analysis.ts` with `getFilteredAnalysis(db, sentenceId)`:
   - Query all words linked to this sentence via `sentence_words` JOIN `words` JOIN `word_senses`
   - Query all collocations via `sentence_collocations` JOIN `collocations`
   - Query all grammar patterns via `sentence_grammar_patterns` JOIN `grammar_patterns`
   - For words: check `word_senses.familiarity` -- if `never_seen` AND no SRS card exists for that sense, it's "new"
   - For collocations: check if SRS card with `collocation_id` exists -- if no card, it's "new"
   - For grammar: check if SRS card with `grammar_pattern_id` exists -- if no card, it's "new"
   - Also load the sentence's `translation` and `cefrLevel` from `sentences` table
   - Return typed `ReaderAnalysisResult`:
     ```typescript
     interface ReaderAnalysisResult {
       translation: string;
       cefrLevel: string;
       newWords: Array<{ senseId: number; lemma: string; partOfSpeech: string; translation: string; definition: string; cefrLevel: string }>;
       newCollocations: Array<{ collocationId: number; text: string; translation: string; type: string; cefrLevel: string }>;
       newGrammarPatterns: Array<{ grammarPatternId: number; pattern: string; description: string; cefrLevel: string }>;
       existingWordsCount: number;
       existingCollocationsCount: number;
       existingGrammarPatternsCount: number;
     }
     ```
   - Use batch queries (one per entity type), not N+1. Follow the raw SQL pattern from `word-highlighter.ts` if Drizzle joins are awkward.

2. Add endpoints to `src/routes/books.ts`:

   a) `POST /books/sentences/:bookSentenceId/analyze`:
      - Look up book_sentence by id. 404 if not found.
      - If `bookSentence.sentenceId` is NOT NULL (cached -- ANAL-02): call `getFilteredAnalysis(db, sentenceId)` and return `{ status: 'completed', result }` (200)
      - If NULL (uncached -- ANAL-01): queue job via `fastify.analysisQueue.add('sentence-analysis', { text: bookSentence.text, bookSentenceId })` and return `{ status: 'queued', jobId: job.id }` (202)

   b) `GET /books/sentences/:bookSentenceId/analyze/status/:jobId`:
      - Get job from `fastify.analysisQueue.getJob(jobId)`. 404 if not found.
      - If completed: the job processor already linked `book_sentences.sentence_id`. Re-read `bookSentence` to get `sentenceId`, then call `getFilteredAnalysis(db, sentenceId)` and return `{ status: 'completed', result }`
      - If failed: return `{ status: 'failed', error: job.failedReason }`
      - Otherwise: return `{ status: state }` (waiting/active)

   c) `POST /reader/words/:senseId/learn`:
      - Update `word_senses` set `familiarity = 'seen_unsure'` where id = senseId
      - Check if SRS card exists for this sense (cardType='vocabulary', wordSenseId=senseId)
      - If not exists: create SRS card using `createEmptyCard()` from ts-fsrs (same pattern as analysis.ts lines 115-128)
      - Return `{ ok: true, status: 'learning' }`

   d) `POST /reader/words/:senseId/know`:
      - Update `word_senses` set `familiarity = 'understand_in_context'` where id = senseId
      - Do NOT create SRS card
      - Return `{ ok: true, status: 'known' }`

   e) `POST /reader/collocations/:collocationId/learn`:
      - Create SRS card (cardType='collocation', collocationId) if not exists
      - Return `{ ok: true }`

   f) `POST /reader/collocations/:collocationId/know`:
      - No action needed (collocation already stored by storeAnalysisResults, just no SRS card)
      - Return `{ ok: true }`

   g) `POST /reader/grammar/:grammarPatternId/learn`:
      - Create SRS card (cardType='grammar', grammarPatternId) if not exists
      - Also queue exercise generation (same pattern as analysis.ts lines 267-278)
      - Return `{ ok: true }`

   h) `POST /reader/grammar/:grammarPatternId/know`:
      - No action needed
      - Return `{ ok: true }`

   Import `createEmptyCard` from 'ts-fsrs', import schema tables needed, import `getFilteredAnalysis` from reader-analysis service.

   IMPORTANT (FLOW-02): The reader analysis path does NOT call `shouldAutoAddWord()`. All words are shown to the user regardless of CEFR level. The `autoCreateSrsCards: false` flag in the job processor handles this.
