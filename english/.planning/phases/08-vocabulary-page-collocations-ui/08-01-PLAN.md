  <action>
Create src/routes/vocabulary.ts as a Fastify plugin (plain export, NOT wrapped in fp() -- follows project route convention).

**GET /vocabulary endpoint:**
1. Parse query params: page (default 1), limit (default 50, max 100), search, familiarity, cefrLevel, cluster, srsState, sortBy (default 'lemma'), sortOrder (default 'asc').

2. Build WHERE conditions array:
   - search: `ilike(words.lemma, '%${search}%')` -- use Drizzle's ilike
   - cefrLevel: `eq(words.cefrLevel, cefrLevel)`
   - cluster: `eq(words.thematicCluster, cluster)`
   - familiarity: requires a subquery -- word has at least one sense with this familiarity
   - srsState: 'none' means word has NO srs card for any sense (LEFT JOIN IS NULL); 'new'/'learning'/'review' means at least one card in that state

3. Strategy to avoid duplicates with multiple senses: Query words first (with filters, pagination, sorting), then batch-fetch senses and SRS state for the page of words.
   - Step 1: SELECT DISTINCT words.* with filters, sort, limit/offset to get the word IDs for this page
   - Step 2: COUNT query for total (same filters, no limit)
   - Step 3: Fetch all word_senses for those word IDs
   - Step 4: Fetch SRS card state for those sense IDs
   - Step 5: Assemble response, grouping senses under each word

4. Sort implementation:
   - lemma: `asc(words.lemma)` or `desc(words.lemma)`
   - date: `asc(words.createdAt)` or `desc(words.createdAt)`
   - cefr: Use SQL CASE expression: `CASE words.cefr_level WHEN 'A1' THEN 1 WHEN 'A2' THEN 2 WHEN 'B1' THEN 3 WHEN 'B2' THEN 4 WHEN 'C1' THEN 5 WHEN 'C2' THEN 6 ELSE 7 END`

5. For srsState filter on the word-level query, use EXISTS subquery:
   - srsState='none': NOT EXISTS (SELECT 1 FROM srs_cards JOIN word_senses ON ... WHERE word_senses.word_id = words.id AND card_type='vocabulary')
   - srsState='new': EXISTS (SELECT 1 FROM srs_cards JOIN word_senses ON ... WHERE word_senses.word_id = words.id AND state='new' AND card_type='vocabulary')

6. The hasCard and srsState fields on each item are computed from the batch-fetched SRS data: hasCard = any sense has a card, srsState = pick the "most active" state across senses (learning > relearning > new > review > null).

Then implement the test cases from Task 1 for the list endpoint (remove todos, write real assertions).

Register the route: Fastify autoload will pick it up from src/routes/vocabulary.ts automatically.

  <action>
Add to src/routes/vocabulary.ts:

**GET /vocabulary/:wordId:**
1. Fetch the word by ID. Return 404 if not found.
2. Fetch all word_senses for this word, LEFT JOIN srs_cards (where cardType='vocabulary') to include SRS card data per sense.
3. Fetch collocations via indirect path: sentenceWords (wordId=X) -> sentenceCollocations (same sentenceId) -> collocations. Use selectDistinct to avoid duplicates when a word appears in multiple sentences that share a collocation.
4. Fetch word family: if word.wordFamilyId is not null, select all words with the same wordFamilyId excluding self.
5. Fetch sentences: join sentenceWords to sentences for this wordId.
6. Return assembled response matching WordDetailResponse shape from research.

**POST /vocabulary/:wordId/mark-known:**
1. Find all word_sense IDs for this word.
2. Delete from srs_cards where cardType='vocabulary' AND wordSenseId IN (sense IDs).
3. Return { success: true }.

**POST /vocabulary/:wordId/reset:**
1. Find all word_sense IDs for this word.
2. For each sense, check if an SRS card already exists (check-then-insert pattern, same as Phase 7 auto-add).
3. For senses without a card, insert a new srs_card with cardType='vocabulary', wordSenseId=sense.id, state='new'.
4. Return { success: true, created: N } where N is the number of new cards created.

Implement all remaining test cases from Task 1 for detail/mark-known/reset. Ensure collocation test verifies the indirect sentence join path works correctly.
