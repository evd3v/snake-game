# English Tutor: очередь слов, разбор и повторение через Telegram и веб

Дата: 2026-09-13. Статус: черновик на согласование.

## 1. Цель и рамки

Евгений учит английский до C1 в чтении (сейчас B1-B2). Нужен инструмент, которым он
управляет сам, без расписания: вызвал команду, получил следующий элемент с разбором,
решил «понял / знаю / объясни», потом проверяет себя по карточкам с интервальным
повторением. Два входа с одним состоянием: группа в Telegram с личным ассистентом
(@evgeniy_personal_assistant_bot, чат `-5548139504`) и простой веб-дашборд.

Не делаем в v1: аудио, грамматику, чтение книг, нескольких пользователей,
напоминания по расписанию (заготовка есть, выключена), пачки элементов.

## 2. Архитектура

Три части, одно состояние:

- **Сервер `english-tutor`** на `aventra` (домен english.evm.im, порт 3101, вместо
  легаси-приложения english-ai). Node 22, Fastify, SQLite (better-sqlite3, файл в
  volume), ts-fsrs. Держит очередь, карточки, историю, кэш разборов. Генерирует
  разбор и проверочные предложения через LLM. Отдаёт API и дашборд.
- **Telegram** через bot-lite на `work`: бот «general» получает сообщения из группы
  без упоминания, воркер (Claude) в роли репетитора. Состояние не хранит: зовёт API
  скриптом `tutor.mjs` (тонкий HTTP-клиент) и пересказывает ответ. Свободные вопросы
  объясняет сам, итог объяснения сохраняет заметкой к карточке.
- **Дашборд**: статичный HTML + vanilla JS, отдаётся сервером. Те же операции, что и
  в Telegram, плюс список и карточка с историей. Для быстрого цикла повторения
  (кнопки, без задержек bot-lite).

Почему сервер, а не файлы на work: у дашборда и Telegram должно быть одно состояние
и одна генерация текстов; на aventra уже есть nginx, домен, Docker и ключи LLM.

## 3. Данные

### 3.1 Источники очереди (одноразовый импорт, результат коммитится в `data/`)

| Поток | Источник | Что берём |
|---|---|---|
| `word` | Oxford 5000 с уровнями CEFR (открытый датасет с определениями и примерами OUP) | слова B2 и C1: заголовок, часть речи, уровень, определения, примеры |
| `pv` | PHaVE List (Garnier & Schmitt, 2015), 150 фразовых глаголов | глагол, ключевые значения с процентом частоты и примером |
| `expr` | PHRASE List (Martinez & Schmitt, 2012), 505 выражений; Oxford Phrase List, полосы B2 и C1 | выражение, значение, пример, частотная полоса или уровень |

Дубли между источниками сливаются по нормализованному заголовку (фразовые глаголы из
Oxford Phrase List уходят в поток `pv`, если есть в PHaVE).

### 3.2 Группировка и порядок

- Скрипт `tag-roots` один раз размечает каждое слово через LLM: латинский или
  греческий корень (если есть) с его значением, семья однокоренных внутри списка,
  «близнец по переводу» (слово с тем же русским переводом, если есть в списке).
  Результат кэшируется в `data/roots.json` и коммитится: повторный запуск ничего не
  перегенерирует.
- Модуль = слова одного корня или семьи; фразовые глаголы группируются по частице;
  выражения идут по частотной полосе.
- Порядок очереди: модули по убыванию размера (самые продуктивные корни первыми),
  внутри модуля по уровню (B2 раньше C1). Слова без корня вперемешку между
  модулями, чтобы подряд не шло 40 латинизмов. Потоки перемежаются в пропорции
  6 слов : 2 фразовых : 2 выражения. Тематических групп (цвета, эмоции) нет
  намеренно: они путаются между собой.

### 3.3 Модель карточки

```
cards
  id, kind (word|pv|expr), headword, pos, level,
  source_json          -- определения, примеры, значения PHaVE, семья, близнец
  group_key, group_label, order_index
  status: queued | shown | discussing | learning | known | suspended
  explanation_md       -- кэш разбора, null до первого показа
  shown_at, decided_at
  fsrs: due, stability, difficulty, elapsed_days, scheduled_days, reps, lapses,
        state (0 new,1 learning,2 review,3 relearning), last_review
review_log: id, card_id, ts, rating (1..4), test_type, sentence, answer, elapsed_ms
notes:      id, card_id, ts, text
settings:   key, value (курсор, режим напоминаний, пароль-хэш не здесь, он в env)
```

Определения статусов:
- `shown`: показан по `/next`, решение не принято. Последний показанный это
  «текущий»: «ок» и «знаю» без уточнения относятся к нему. Старые нерешённые
  висят в дашборде в списке «отложено», решаются оттуда или фразой «ок про bleak».
- `discussing`: задан вопрос по элементу, ждём «ок».
- `learning`: в повторении (FSRS). «Выучено» для статуса = state review и интервал
  ≥ 21 дня, как mature в Anki.
- `known`: «знаю», в повторение не идёт, в статус попадает как «знал заранее».

### 3.4 Статус

`всего / показано / учу / выучено / знал заранее / осталось в очереди / ждёт
повторения сегодня`, отдельно по потокам и суммой.

## 4. API (Fastify, JSON, Bearer-токен для клиента на work, cookie для дашборда)

```
GET  /api/status                       -> счётчики
GET  /api/next?kind=word|pv|expr       -> следующий элемент + разбор (генерирует и кэширует)
POST /api/cards/:id/learn              -> shown|discussing -> learning (FSRS new)
POST /api/cards/:id/known              -> -> known
POST /api/cards/:id/discuss            -> shown -> discussing
POST /api/cards/:id/notes  {text}      -> заметка (итог объяснения из чата)
GET  /api/pending                      -> текущий показанный элемент
GET  /api/review/next                  -> {card, test_type, sentence, answer, left_today} | null
POST /api/review/:id/grade {rating}    -> FSRS-переход, возвращает новый due
GET  /api/cards?status=&kind=&q=       -> список
GET  /api/cards/:id                    -> карточка, разбор, история, заметки
POST /api/cards/:id/suspend            -> убрать из повторения
```

`tutor.mjs` на work: `node tutor.mjs next [kind] | learn | known | discuss | note "…"
| status | review | grade <1-4> | pending`. Без аргумента `id` действует на текущий
показанный элемент или на текущую проверочную карточку. Печатает готовый текст для
Telegram (markdown bot-lite), воркер вставляет его в ответ как есть.

## 5. Сценарии в Telegram

Инструкция репетитора `TUTOR.md` лежит в репозитории и подключается через память
бота general: «если chat_id = -5548139504, прочитай TUTOR.md и работай по нему».
Правила из TUTOR.md:

- `/next`, «дальше», «ещё» → `tutor.mjs next`, текст разбора без пересказа. Ровно один
  элемент. `/next фразовый`, `/next выражение` выбирают поток.
- «ок», «понял», 👍 на сообщении с разбором → `tutor.mjs learn`, ответ одной строкой:
  «в очереди повторения, всего учу N». «Знаю» → `known`.
- Вопрос по элементу («а чем от vary», «пример с работой») → `discuss`, объяснить
  самому по данным разбора и своим знаниям, в конце спросить «ок?». После «ок» →
  `learn` и `note` с итогом объяснения в одну-две строки.
- `/review` → `tutor.mjs review`: сообщение с предложением, ответ под спойлером,
  строка «1 снова · 2 трудно · 3 норм · 4 легко». Ответ цифрой или словом
  («не понял» = 1, «понял» = 3) → `grade`, затем сразу следующая карточка, пока не
  «стоп» или не кончились. Без пачек, по одной.
- `/status` → `tutor.mjs status`.
- Честность: разница слов и корень берутся из данных карточки; если данных нет, так
  и сказать («в списках разницы нет, по моему пониманию …»), не выдумывать этимологию.
- Стиль: по-русски, коротко, без длинного тире, примеры на английском.

Ограничение платформы: ответ бота приходит примерно через минуту (дебаунс 25 секунд
плюс прогон). Для быстрого цикла повторения есть дашборд. Возможное улучшение позже:
дебаунс на чат в bot-lite.

## 6. Проверка знаний (review)

- Карточка выбирается по FSRS: `due <= now`, раньше та, что просрочена сильнее.
- Предложение каждый раз новое. Генерируется сервером в момент запроса: содержит
  заголовок (словоформа допускается), 12-22 слова, уровень B2, смысл однозначен из
  контекста, для фразового глагола ключевое значение по PHaVE, не совпадает с
  примером из разбора и с последними пятью предложениями этой карточки (передаются в
  промпт, сервер проверяет детерминированно: заголовок присутствует, длина в норме,
  текст не из истории; при провале одна повторная генерация, потом запасной пример
  из источника с пометкой).
- Типы теста: `context` (предложение, ответ: значение по-русски одной строкой плюс
  английский глосс) для всех; `cloze` (то же предложение с пропуском и русской
  подсказкой, ответ: заголовок) чередуется с `context` у карточек с reps ≥ 3, чтобы
  зрелые слова проверялись и на воспроизведение.
- Оценка 1..4 = FSRS Again/Hard/Good/Easy. Переход через ts-fsrs с параметрами по
  умолчанию, `request_retention 0.9`. Лог пишется с предложением и ответом.
- В Telegram ответ прячется спойлером: bot-lite получает поддержку `||текст||` →
  `<tg-spoiler>` в конвертере markdown (правка движка на три строки плюс тест).

## 7. Дашборд (v1)

Одна страница, вкладки: **Статус** (счётчики, ждёт сегодня, серия дней),
**Учить** (следующий элемент, кнопки «Учу» / «Знаю» / «Отложить», поле вопроса нет:
вопросы в Telegram), **Повторение** (предложение → «Показать ответ» → четыре кнопки,
следующая карточка сразу), **Список** (фильтр по статусу и потоку, поиск),
**Карточка** (разбор, история оценок, заметки, кнопка «убрать из повторения»).
Вход по паролю из env, cookie на 30 дней. Мобильная вёрстка, тёмная тема по системе.

## 8. Генерация текстов

- Провайдер: OpenAI-совместимый endpoint cloud.ru с существующим ключом
  (`AI_PROVIDER=cloudru`), модель из env: `anthropic/claude-opus-5`, если доступна,
  иначе `anthropic/claude-sonnet-4.6`. Запасной провайдер OpenAI по ключу из env.
- Разбор (`/api/next`) строится из данных карточки и промпта-шаблона: значение
  по-русски одной-двумя строками; строение (приставка, корень, суффикс) только если
  корень размечен; семья и соседи по корню из списка; 2-3 сочетания; «не путать с …»
  только если размечен близнец; один пример из источника. Для фразового глагола:
  значение частицы и 1-3 ключевых значения с процентами PHaVE. Для выражения:
  значение, регистр, пример. Формат фиксирован, промпт в `prompts/explain.md`.
- Проверочное предложение: `prompts/test.md`, см. раздел 6.
- Кэш: разбор один раз на карточку; предложения не кэшируются.

## 9. Деплой и конфигурация

- Репозиторий `personal`, папка `english-tutor/`. Docker Compose на aventra в
  `~/english-tutor/`, volume `data/` с SQLite, порт 3101 (легаси-контейнеры
  english останавливаются, их volume не удаляется до отдельного решения).
  nginx для english.evm.im проксирует всё на 3101, статический корень
  `/var/www/english` больше не используется.
- Секреты в `.env` на сервере: `API_TOKEN` (случайный, для work), `DASHBOARD_PASSWORD`,
  ключи LLM. На work: `~/.claude/english-tutor.env` с `API_URL` и `API_TOKEN`.
- bot-lite (без правок движка кроме спойлера): `access.json` бота general получает
  группу `-5548139504` с `requireMention: false`; в `memory/general/00-operating-memory.md`
  абзац про режим репетитора и путь к `TUTOR.md`; `TUTOR.md` и `tutor.mjs` лежат в
  клоне репозитория на work (`~/projects/english-tutor`).
- Напоминание «ждёт повторения N» в 21:00: серверный cron, включается переменной
  `REMINDER_AT`, по умолчанию пусто. Отправка через Bot API токеном бота general
  (`TELEGRAM_BOT_TOKEN` на сервере, только если напоминание включено).

## 10. Тесты

- Импорт и очередь: парсеры списков на фикстурах, слияние дублей, пропорция
  потоков, порядок модулей, детерминированность при повторном запуске.
- FSRS: оценка 1 возвращает в relearning, 3 и 4 увеличивают интервал, «выучено»
  считается по порогу 21 дня.
- API: сквозные тесты на SQLite в памяти, LLM подменён заглушкой; правила
  «текущий элемент», статусы, счётчики.
- Генерация: детерминированная проверка предложений (заголовок, длина, история).
- bot-lite: тест конвертера на `||спойлер||`.
- Ручная проверка: `/next` → 👍 → `/review` → оценка в группе; дашборд на телефоне.

## 11. Решения по умолчанию (можно поменять)

1. Хостинг на aventra вместо легаси english-ai, тот же домен и порт.
2. LLM через cloud.ru существующим ключом; модель opus, если доступна.
3. Правка bot-lite ради спойлера. Альтернатива без правки: ответ отдельным
   сообщением после оценки, но тогда самооценка «вслепую».
4. Порог «выучено» 21 день; пропорция потоков 6:2:2; уровни B2 и C1 (B1 можно
   добавить позже отдельным режимом «аудит»).
